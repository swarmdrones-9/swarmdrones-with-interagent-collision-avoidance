# Path Controller for Multi-Vehicle Formation

This directory contains scripts for controlling the leader drone along predefined paths and visualizing the results.

## Files

- `path_controller.py` - Controls leader drone along predefined paths (square, circle, figure-8)
- `visualize_path.py` - Post-processes CSV data and generates visualization plots

## Usage

### 1. Start C++ Multi-Vehicle Controller

First, start the C++ controller to handle takeoff and follower control:

```bash
cd ~/ws_offboard_control
source /opt/ros/jazzy/setup.bash
source install/local_setup.bash

# Build if needed
colcon build --packages-select px4_ros_com
source install/local_setup.bash

# Run multi-vehicle controller
./install/px4_ros_com/lib/px4_ros_com/multi_vehicle_offboard_control --num_drones 5
```

Wait ~15 seconds for drones to take off and stabilize.

### 2. Start Path Controller (Python)

In a new terminal (IMPORTANT: Source ROS 2 environment first):

```bash
cd ~/ws_offboard_control
source /opt/ros/jazzy/setup.bash
source install/local_setup.bash

# Run path controller
python3 src/px4_ros_com/src/examples/offboard_py/path_controller.py \
    --path square \
    --speed 2.0 \
    --num_drones 5
```

**Note:** You MUST source the ROS 2 setup files before running the Python script, otherwise you'll get `ModuleNotFoundError: No module named 'rclpy'`

**Arguments:**
- `--path`: Path type (`square`, `circle`, or `figure8`)
- `--speed`: Path speed in m/s (default: 2.0)
- `--num_drones`: Number of drones (default: 5)
- `--square_size`: Square path size in meters (default: 10.0)
- `--circle_radius`: Circle path radius in meters (default: 5.0)
- `--figure8_size`: Figure-8 path size in meters (default: 8.0)

**Example commands:**
```bash
# Square path at 2.0 m/s
python3 src/px4_ros_com/src/examples/offboard_py/path_controller.py --path square --speed 2.0

# Circle path at 3.0 m/s
python3 src/px4_ros_com/src/examples/offboard_py/path_controller.py --path circle --speed 3.0

# Figure-8 path at 1.5 m/s
python3 src/px4_ros_com/src/examples/offboard_py/path_controller.py --path figure8 --speed 1.5
```

The script will:
- Wait 15 seconds for C++ to handle takeoff
- Control leader along the selected path
- Log all drone positions to CSV file (e.g., `square_2.0ms_20251127_103045.csv`)
- Exit when path is complete

### 3. Visualize Results

After the path is complete, visualize the data:

```bash
python3 src/px4_ros_com/src/examples/offboard_py/visualize_path.py \
    square_2.0ms_20251127_103045.csv \
    --num_drones 5 \
    --output_dir ./plots
```

**Arguments:**
- `csv_file`: Path to CSV file generated by path_controller.py
- `--num_drones`: Number of drones (default: 5)
- `--output_dir`: Directory to save plots (default: current directory)
- `--no-show`: Don't display plots, only save files

**Generated Plots:**
- `*_2d.png` - 2D top-down view of all drone paths
- `*_3d.png` - 3D view of all drone paths
- `*_separation.png` - Separation distances between drone pairs over time
- `*_formation_error.png` - Formation error (deviation from desired positions)

## Testing Different Speeds

To find optimal speed for formation keeping:

1. Test at slow speed (1.0 m/s) - baseline
2. Gradually increase (2.0, 3.0, 4.0 m/s)
3. Compare metrics:
   - Minimum separation distance
   - Average formation error
   - Path completion time

Example workflow:
```bash
# Test 1: Slow speed
python3 src/px4_ros_com/src/examples/offboard_py/path_controller.py --path square --speed 1.0
python3 src/px4_ros_com/src/examples/offboard_py/visualize_path.py square_1.0ms_*.csv

# Test 2: Medium speed
python3 src/px4_ros_com/src/examples/offboard_py/path_controller.py --path square --speed 2.0
python3 src/px4_ros_com/src/examples/offboard_py/visualize_path.py square_2.0ms_*.csv

# Test 3: Fast speed
python3 src/px4_ros_com/src/examples/offboard_py/path_controller.py --path square --speed 3.0
python3 src/px4_ros_com/src/examples/offboard_py/visualize_path.py square_3.0ms_*.csv
```

## CSV File Format

The CSV file contains:
- `timestamp`: Time in seconds
- `drone_id`: Drone ID (0=leader, 1-4=followers)
- `x`, `y`, `z`: Position in meters (local NED frame)
- `waypoint_idx`: Current waypoint index

## Notes

- The Python script publishes at 50 Hz to ensure it overrides C++ control (which publishes at 20 Hz)
- Leader control is taken over by Python, C++ continues handling followers
- Path completion is detected when leader reaches final waypoint
- All positions are logged at 50 Hz for detailed analysis

## Troubleshooting

**Leader not following path:**
- Make sure C++ controller is running first
- Wait for 15 seconds after starting C++ before starting Python script
- Check that leader is in offboard mode

**No data in CSV:**
- Ensure all drones are publishing position data
- Check ROS 2 topic: `ros2 topic echo /px4_1/fmu/out/vehicle_local_position`

**Plots not generating:**
- Install matplotlib: `pip3 install matplotlib numpy`
- Check CSV file exists and has data
